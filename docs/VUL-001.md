# VUL-001: BOLA/IDOR - Broken Object Level Authorization

## Finding Metadata

- **Finding ID**: VUL-001
- **Title**: BOLA/IDOR - Broken Object Level Authorization
- **Date**: 2026-10-02
- **Category**: Authorization
- **CWE**: CWE-639 - Authorization Framework Risk
- **OWASP Reference**: A01:2021 - Broken Access Control
- **Severity**: High (explicit rationale: unauthorized cross-user data access with read/modify/delete capabilities)
- **Validation Status**: Confirmed (code review + automated reproduction); remediation implemented and retested (18/18 tests pass)

## Technical Details

### Affected Endpoints

| Endpoint | HTTP Method | Source File | Lines |
|----------|-------------|-------------|-------|
| `/records/{record_id}` | GET | `app/main.py` | 231-250 |
| `/records/{record_id}` | PUT | `app/main.py` | 253-276 |
| `/records/{record_id}` | DELETE | `app/main.py` | 279-297 |
| `/records` | GET (list all) | `app/main.py` | 195-206 |

### Root Cause

The `/records/{record_id}` endpoint and related operations perform no ownership validation. The SQL query `db.query(Record).filter(Record.id == record_id).first()` retrieves any record by ID regardless of who owns it. The `owner_id` foreign key exists on the Record model (CWE-328 missing invalid input validation, but here used as authorization bypass) but is never checked against the authenticated user's ID in the vulnerable implementation.

### Vulnerable Code Excerpts

**`app/main.py:231-250` - get_record endpoint:**
```python
record = db.query(Record).filter(Record.id == record_id).first()
if not record:
    raise HTTPException(status_code=404, detail="Record not found")
return {
    "id": record.id,
    "title": record.title,
    "content": record.content,
    "owner": record.owner.username if record.owner else None,
}
# No ownership check: record.owner_id == current_user.id is missing
```

**`app/main.py:195-206` - list_records endpoint:**
```python
@app.get("/records", response_model=list)
def list_records(
    db=Depends(get_db),
    current_user=Depends(get_current_user),
):
    """List all records.
    
    Vulnerable version: No ownership validation - returns ALL records.
    Secured version: Only returns records owned by the current user.
    """
    records = db.query(Record).all()
    return records
# Returns ALL records; no owner_id filter
```

### Preconditions

1. User must be authenticated (any role: user or admin)
2. Target record must exist in the database
3. The authenticated user must NOT be the record owner (for exploitation)

### Security Impact

| Impact Area | Level | Description |
|-------------|-------|-------------|
| **Confidentiality** | High | Alice can read Bob's private records (medical data, financial reports) without authorization |
| **Integrity** | High | Alice can modify or delete Bob's records without authorization, altering/ destroying his data |
| **Availability** | High | Alice can delete Bob's records, destroying his data |
| **Required Privileges** | None needed | Any authenticated user (even regular 'user' role) can exploit; no admin privileges required |
| **Scope** | Single-user local lab | Vulnerability contained to synthetic test data; real-world impact would be unauthorized cross-user data access |

### Remediation

**Recommended Fix**: Add ownership validation to all record operations in `app/main.py`.

```python
# For get_record (line 231-250):
record = db.query(Record).filter(
    Record.id == record_id, 
    Record.owner_id == current_user.id  # ADD THIS CHECK
).first()
if not record:
    raise HTTPException(status_code=404, detail="Record not found")

# For update_record (line 253-276):
record = db.query(Record).filter(
    Record.id == record_id, 
    Record.owner_id == current_user.id  # ADD THIS CHECK
).first()
if not record:
    raise HTTPException(status_code=404, detail="Record not found")
# ... proceed with update

# For delete_record (line 279-297):
record = db.query(Record).filter(
    Record.id == record_id, 
    Record.owner_id == current_user.id  # ADD THIS CHECK
).first()
if not record:
    raise HTTPException(status_code=404, detail="Record not found")
# ... proceed with delete
```

**Expected Secure Behavior After Fix (implemented as `/secure/` counterparts in Phase 3B):**

- `GET /secure/records/3` as Alice → 404 (record 3 owned by Bob, not Alice)
- `PUT /secure/records/3` as Alice → 404 (ownership violation)
- `DELETE /secure/records/3` as Alice → 404 (ownership violation)
- `GET /secure/records` as Alice → returns only Alice's records (IDs 1, 2)
- `GET /secure/records/1` as Alice → 200 (owner access permitted)

**Alternative Secure Design**: Implement role-based access control where each endpoint explicitly checks `current_user.role` and `Record.owner_id == current_user.id` before any operation.

### Validation Limitations

1. **Environment**: All tests executed via FastAPI Test Client; no browser-based XSS verification
2. **Scope**: Limited to local synthetic data (3 users, 4 records); real-world deployment would require additional session management, rate limiting, and audit logging
3. **Completion Mechanism**: Server-side lab completion verification at `POST /labs/bola/complete` exists but was not fully tested in this phase (PowerShell server startup issues)
4. **No privilege escalation beyond record access**: Tests confirm record-level BOLA but do not test broader admin privilege escalation (separate VUL-002 finding)
5. **Single connection scenario**: Tests do not simulate concurrent users or race conditions

### Additional Notes

- The vulnerability is intentional and preserved as a training challenge for security education
- The secured version of the application should implement ownership checks on all record operations
- The `/api/records` endpoint (`app/main.py:354-368`) already implements secure filtering by `owner_id == current_user.id` — this was initially mischaracterized in the first validation report as "no access control" but was corrected based on code review
- The `list_records` endpoint returns all records without ownership filter by design (vulnerable version); the secured counterpart would add `filter(Record.owner_id == current_user.id)`
