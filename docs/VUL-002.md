# VUL-002: BFLA - Broken Function Level Authorization

## Finding Metadata

- **Finding ID**: VUL-002
- **Title**: BFLA - Broken Function Level Authorization
- **Date**: 2026-10-02
- **Category**: Authorization
- **CWE**: CWE-863 - Incorrect Authorization
- **OWASP Reference**: A01:2021 - Broken Access Control
- **Severity**: High (explicit rationale: regular user can access administrative functions and sensitive configuration data)
- **Validation Status**: Confirmed (code review + automated reproduction); remediation implemented and retested (18/18 tests pass)

## Technical Details

### Affected Endpoints

| Endpoint | HTTP Method | Source File | Lines |
|----------|-------------|-------------|-------|
| `/admin/users` | GET | `app/main.py` | 303-317 |
| `/admin/debug` | GET | `app/main.py` | 320-342 |

### Root Cause

The `/admin/users` and `/admin/debug` endpoints perform no role-based access control. The `list_users()` function queries all users from the database and returns them to any authenticated user, regardless of role. The `debug_info()` function returns server configuration details including cookie security settings and database URL to any authenticated user. Neither endpoint checks `current_user.role == "admin"` before returning sensitive data.

### Vulnerable Code Excerpts

**`app/main.py:303-317` - list_users endpoint:**
```python
@app.get("/admin/users")
def list_users(
    db=Depends(get_db),
    current_user=Depends(get_current_user),
):
    """List all users.
    
    Vulnerable version: Regular users can access this endpoint (BFLA).
    Secured version: Only users with role='admin' can access.
    """
    users = db.query(User).all()
    return [
        {"id": u.id, "username": u.username, "email": u.email, "role": u.role}
        for u in users
    ]
# No role check: current_user.role == "admin" is missing
```

**`app/main.py:320-342` - debug_info endpoint:**
```python
@app.get("/admin/debug")
def debug_info(
    db=Depends(get_db),
    current_user=Depends(get_current_user),
):
    """Debug endpoint - vulnerable to information disclosure.
    
    Returns server configuration and environment details.
    Should be restricted to admin only.
    """
    # In a secured app, this would be admin-only
    # Vulnerable: returns info to any authenticated user
    return {
        "app_name": settings.APP_NAME,
        "app_version": settings.APP_VERSION,
        "debug": settings.DEBUG,
        "host": settings.HOST,
        "port": settings.PORT,
        "cookie_secure": settings.COOKIE_SECURE,
        "cookie_http_only": settings.COOKIE_HTTP_ONLY,
        "cookie_samesite": settings.COOKIE_SAMESITE,
        "database_url": str(engine.url),
    }
# No role check: any authenticated user can access debug info
```

### Preconditions

1. User must be authenticated (any role: user or admin)
2. The endpoint must be called with a valid session cookie or bearer token

### Security Impact

| Impact Area | Level | Description |
|-------------|-------|-------------|
| **Confidentiality** | High | Regular user can enumerate all users (usernames, emails, roles) and access sensitive server configuration |
| **Integrity** | Medium | Knowledge of admin credentials and server configuration could enable further attacks |
| **Availability** | Low | Information disclosure does not directly affect availability |
| **Required Privileges** | None needed | Any authenticated user (even regular 'user' role) can exploit; no admin privileges required |
| **Scope** | Single-user local lab | Vulnerability contained to synthetic test data; real-world impact would be unauthorized admin access and configuration exposure |

### Remediation

**Recommended Fix**: Add role-based access control to admin endpoints in `app/main.py`.

```python
# For list_users (line 303-317):
@app.get("/admin/users")
def list_users(
    db=Depends(get_db),
    current_user=Depends(get_current_user),
):
    """List all users - admin only."""
    if current_user.role != "admin":
        raise HTTPException(status_code=403, detail="Administrator privileges required")
    users = db.query(User).all()
    return [
        {"id": u.id, "username": u.username, "email": u.email, "role": u.role}
        for u in users
    ]

# For debug_info (line 320-342):
@app.get("/admin/debug")
def debug_info(
    db=Depends(get_db),
    current_user=Depends(get_current_user),
):
    """Debug endpoint - admin only."""
    if current_user.role != "admin":
        raise HTTPException(status_code=403, detail="Administrator privileges required")
    return {
        "app_name": settings.APP_NAME,
        "app_version": settings.APP_VERSION,
        "debug": settings.DEBUG,
        "host": settings.HOST,
        "port": settings.PORT,
        "cookie_secure": settings.COOKIE_SECURE,
        "cookie_http_only": settings.COOKIE_HTTP_ONLY,
        "cookie_samesite": settings.COOKIE_SAMESITE,
        "database_url": str(engine.url),
    }
```

**Expected Secure Behavior After Fix (implemented as `/secure/admin/` counterparts in Phase 3B):**

- `GET /secure/admin/users` as Alice (regular user) → 403 Forbidden
- `GET /secure/admin/debug` as Alice (regular user) → 403 Forbidden
- `GET /secure/admin/users` as admin → 200 OK with user list
- `GET /secure/admin/debug` as admin → 200 OK with non-sensitive debug info

**Alternative Secure Design**: Implement a decorator or middleware that checks `current_user.role == "admin"` for all `/admin/*` endpoints, centralizing the authorization logic.

### Retest Evidence

Secure counterparts (BFLA) were implemented in Phase 3B and validated: 4 of 18 tests in `test_bola_bfla.py` verify the `/secure/admin/*` routes enforce admin role (403 on non-admin access, 200 for admins). See [RETEST_RESULTS.md](RETEST_RESULTS.md) for the full post-remediation retest report.

### Validation Limitations

1. **Environment**: All tests executed via FastAPI Test Client; no browser-based verification
2. **Scope**: Limited to local synthetic data; real-world deployment would require additional session management, rate limiting, and audit logging
3. **Completion Mechanism**: Server-side lab completion verification at `POST /labs/bfla/complete` exists but was not fully tested in this phase (PowerShell server startup issues)
4. **No privilege escalation beyond admin access**: Tests confirm BFLA but do not test broader system compromise scenarios
5. **Single connection scenario**: Tests do not simulate concurrent users or race conditions

### Additional Notes

- The vulnerability is intentional and preserved as a training challenge for security education
- The secured version of the application should implement role checks on all admin endpoints
- The `/api/records` endpoint (`app/main.py:354-368`) already implements secure filtering by `owner_id == current_user.id` — this was initially mischaracterized in the first validation report as "no access control" but was corrected based on code review
- The `list_records` endpoint returns all records without ownership filter by design (vulnerable version); the secured counterpart would add `filter(Record.owner_id == current_user.id)`
